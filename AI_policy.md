# AI Policy

You are allowed to use AI tools (such as ChatGPT, GitHub Copilot, or Claude) in a limited way during this project. 
Understanding the rules is part of working professionally.

## What is allowed
- Using AI to **explain a concept** you do not understand (e.g. "How does Socket.IO work?")
- Using AI to help **interpret an error message** or debug a specific problem
- Using AI to **review a piece of code you wrote** and suggest improvements

## What is not allowed
- Using AI to **generate complete features or user stories** for you
- Using AI to **generate documentation** for you (e.g. `README.md`, `CODE_REVIEW.md`, `RETROSPECTIVE.md`)
- Submitting code you **cannot explain yourself**

## Why these rules exist
The goal of this project is that *you* learn to build a full-stack application. 
If AI writes your code, you miss that learning, and it will show during the code reviews and assessment.

## Documentation requirement
If you used AI in any meaningful way, note it briefly in your `CODE_REVIEW.md` or `RETROSPECTIVE.md`:
- What you asked
- What it gave you
- What you did with it

Not documenting AI use that is later discovered during a code review counts as academic dishonesty.

## During code reviews and assessment
You must be able to explain any line of code in your project. 
You may be asked to make a small live change to your own code.
If you cannot explain or modify your own code, this will affect your assessment negatively, even if the code works.
